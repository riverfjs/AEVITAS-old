# Python Conda Workspace

## Goal

Create reproducible Python workspaces and execute tasks safely in a single managed conda runtime.

## Hard Constraints

- Always use `python-work/<workname>/`; never place task scripts in workspace root or `/tmp`.
- Do not mix `venv` and `conda` for the same task.
- Use `install.sh` and `run.sh`; avoid ad-hoc `pip`/`python` commands.
- Use `list-work.sh` to inspect existing projects before reusing names.
- Any files generated by Python tasks must be written under the current `python-work/<workname>/` only.
- Run `clean.sh` only after explicit user cleanup request.
- Conda env name is fixed: `aevitas-workspace`.

## Workflow

1. Health check / bootstrap:
   - `bash ~/.aevitas/workspace/.claude/skills/python-conda-workspace/scripts/bootstrap.sh`
   - `bash ~/.aevitas/workspace/.claude/skills/python-conda-workspace/scripts/check.sh`
2. Inspect and create workspace:
   - `bash ~/.aevitas/workspace/.claude/skills/python-conda-workspace/scripts/list-work.sh`
   - `bash ~/.aevitas/workspace/.claude/skills/python-conda-workspace/scripts/init-work.sh <workname>`
3. Install dependencies:
   - pip: `bash ~/.aevitas/workspace/.claude/skills/python-conda-workspace/scripts/install.sh --work <workname> <pkg...>`
   - conda/native: `bash ~/.aevitas/workspace/.claude/skills/python-conda-workspace/scripts/install.sh --work <workname> --conda <pkg...>`
4. Run code:
   - file: `bash ~/.aevitas/workspace/.claude/skills/python-conda-workspace/scripts/run.sh --work <workname> --file <file.py>`
   - inline: `bash ~/.aevitas/workspace/.claude/skills/python-conda-workspace/scripts/run.sh --work <workname> --code "<python>"`
5. Cleanup only when user asks:
   - `bash ~/.aevitas/workspace/.claude/skills/python-conda-workspace/scripts/clean.sh <workname> --all`

For CairoSVG-like tasks, install native runtime first (`--conda cairo`) before pip packages.

## Output Template

```markdown
Workspace: <workname>
Environment: aevitas-workspace

Actions:
- Initialized workspace: <yes/no>
- Installed dependencies: <list>
- Executed: <file or inline code>

Result:
- Status: <success/failure>
- Key output: <short snippet>
- Artifacts: <paths under python-work/<workname>>
```

## When NOT to use this skill

- User only needs a quick non-Python shell command.
- Task requires modifying files outside `python-work/<workname>`.
- User explicitly requires a different Python runtime model (not conda-managed).
